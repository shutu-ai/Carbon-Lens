## SQL 支持矩阵

允许的写入形态：

- `CREATE TABLE <configured_workspace>.<configured_prefix><generated_id> AS SELECT ...`
- `INSERT INTO <configured_workspace>.<registered_active_table> SELECT ...`
- `INSERT OVERWRITE TABLE <configured_workspace>.<registered_active_table> SELECT ...`
- `DROP TABLE <configured_workspace>.<registered_active_table>`

只读查询仍走原有 `carbon_query` / `carbon_export` 路径。推荐使用
`carbon_workspace_create_start`，由服务端生成唯一目标名；完整 CTAS SQL 即使通过
`carbon_execute_start` 进入，也必须通过相同 policy、workspace、prefix、reservation 和
远端身份校验。

明确拒绝：原始/第三方/未注册目标，UPDATE、DELETE、MERGE、ALTER、TRUNCATE、RENAME、
CREATE OR REPLACE、CREATE IF NOT EXISTS、CREATE LIKE、DROP DATABASE/SCHEMA、USE、SET、
LOAD DATA、INSERT OVERWRITE DIRECTORY、LOCATION、外部表、未知语法、多语句和无法解析的
目标。注释、大小写、换行、反引号标识符、CTE 和字符串中的分号不会绕过单语句校验。

## 实现与生命周期

- `write_workspace.enabled` 默认 `false`；启用时必须显式配置 schema 和 table prefix，
  不会自动创建或修改 schema。
- `managed_tables` 保存 `table_id`、连接、workspace、限定名、创建 execution、SQL
  fingerprint、状态和验证时间。CTAS 先写 reservation，再启动远端任务。
- 状态为 `reserved → creating → active → dropping → dropped`，并保留
  `create_unknown/create_failed/drop_unknown/drop_failed` 分支。
- `idempotency_key` 绑定连接、操作、目标和 SQL fingerprint；冲突直接拒绝。
- SSH 启动异常、远端状态缺失、超时或最终身份无法确认时返回
  `unknown`/`EXECUTION_UNKNOWN`/`reconciliation_required`，不自动重试、不自动补偿。
- 取消只写入取消请求并返回 `cancel_requested`；最终状态以远端状态为准，不能宣称数据库回滚。
- DDL/DML 结果只返回 execution metadata；`affected_row_count` 固定为未知，不猜测远端输出。

## 未验证项与剩余风险

1. 未连接或写入真实 CarbonData workspace，因此真实 CTAS/INSERT/OVERWRITE/DROP、Beeline 方言和底层权限隔离仍需受控验收。
2. 当前应用层通过限定名 + 注册记录确认归属；Carbon 引擎若支持可读取的稳定对象 ID，应在后续真实环境中补充对象身份绑定。
3. 远端日志只取有界尾部；任何未来扩展都必须继续清理密码、keytab、私钥、连接配置和原始敏感数据。
4. C5（原生 Beeline 对账）和 C6（性能基线/SLA）按任务书明确标记为 **`WAIVED / OUT OF SCOPE`**，不计入本轮 PASS。
