# v0.4 Streamable HTTP 设计

## 目标与边界

v0.4 在保留 stdio、查询、后台任务、导出、SSH/跳板机、Kerberos 和 SFTP 的
前提下，增加标准 MCP Python SDK 的 Streamable HTTP 服务。HTTP 只改变 MCP
传输，不复制 Carbon SQL 或 SSH 逻辑；不引入账号、RBAC、OAuth、Redis 或多副本
状态同步。原始表只读和 `write_workspace.enabled=false` 默认值保持不变。

## 分层

```text
MCP client (stdio | Streamable HTTP /mcp)
                 |
          FastMCP tool registry
                 |
      CarbonLensService / job managers / SQLite
                 |
       local Beeline | SSH | SSH Jump Host + SFTP
                 |
              CarbonData
```

`FastMCP.streamable_http_app()` 和 SDK 的 `StreamableHTTPASGIApp` 负责
initialize、tools/list、tools/call、会话和协议头；代码没有实现自定义 JSON-RPC
网关。当前 `.venv` SDK 版本为 1.30.0，项目依赖约束仍为 `mcp>=1.13,<2`，没有
进行未经回归的升级。

## 生命周期与共享状态

- stdio 继续使用按配置和父 PID 的 `InstanceLock`，可选的父进程监控仍只属于
  stdio。
- HTTP 使用按配置文件的稳定锁，不绑定客户端 PID，也不启动父进程监控；客户端
  断开不会停止服务。
- HTTP 请求共享同一个懒加载的 service、query/export/write manager 和持久化
  SQLite；单例初始化由进程锁保护，任务状态以 query/export/execution ID 为准。
- 服务重启后管理器从同一个 SQLite 文件恢复观察能力，状态请求不会重新提交 SQL。
  现有 manager 的锁和原子文件落盘继续负责导出重试、终态竞争和远端清理。

## 连接保护与配置

`serve` 子命令支持 `--host`、`--port`、`--path`、`--public-base-url`、
`--access-token-env`、`--allowed-host`、`--allowed-origin` 和日志等级。默认只
监听 loopback；非 loopback 启动没有 token 会快速失败。HTTP 使用 bearer token
保护 MCP 与导出下载，并对 Host/Origin 做检查；healthz 不触发后端连接。HTTP
配置可放在 `config.json` 的顶层 `http` 对象，也可由环境变量或 CLI 覆盖。

## 导出交付

后台导出仍由 `carbon_export_start` / `carbon_export_status` 驱动。HTTP 场景的
成功状态保留兼容的 `local_path`，并额外给出 `download_available` 与可信配置
生成的 `download_url`。下载端点只接受 export ID，验证 persisted row、状态、归属
目录和文件存在性，然后由 Starlette `FileResponse` 分块传输；不会接受任意本地
路径，也不会因下载重跑 SQL。未知 ID、未完成、已过期/缺失文件分别返回可诊断的
HTTP 错误；同一 URL 可再次全量下载。Range 断点续传未作为 v0.4 P0 实现。

## local backend

本版本没有新增 local Beeline backend；现有 SSH/Jump Host 路径为 P0 并保持复用。
直接本地 Beeline 仍是 P1 deferred，后续最小方案应复用 `CarbonLensService`、
任务模型、解析器、超时/取消和导出契约，以受控 fake executable 覆盖进程路径，
不得复制 MCP 工具或削弱 SSH 路径。
